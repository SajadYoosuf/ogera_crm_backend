# Product catalogue

## Why
Admins need to keep the tank catalogue (details, specs, price) in one place instead of Excel offer sheets. The real data is connected later; this adds the schema and API.

## What changes
- `models/product.py` (new): `Product` and `ProductOption` (brand / category / material in one table). Soft delete through `deleted_at`.
- `schemas/product.py` (new): create, patch and response models. `sale_price` cannot exceed `mrp`.
- `routes/products.py` (new, registered in `routes/__init__.py` and `main.py`): list, get, create, patch, soft delete, and `/products/options`. Read: any signed-in user; write: admin and manager. `discount_percent` and `you_save` are computed in the response.
- `scripts/migrate_products_table.sql`: the same tables as plain SQL.
- `tests/test_products.py` (new, first backend tests): run with `python -m pytest tests` (needs `pytest` and `httpx`; uses in-memory SQLite).

## Out of scope
Image upload (a URL is stored), bulk import, linking sales or contacts to products, mobile.

## Verification
Six pytest cases pass: discount maths, duplicate slug/SKU 409, price above MRP 422, options and patch, soft delete, role check (read 200, write 403).
