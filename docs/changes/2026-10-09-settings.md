# Settings: editable dropdown options, company profile, permission matrix

## Why
Admins could not change dropdown options (sources, stages, activity types, loss reasons, partner types, districts) or the company name and logo without a code change. Managers had no place to see what each role can do.

## What changes
- New tables `enum_values` and `company_settings`, created on startup and seeded by `settings_catalog.seed_defaults` with the values the app already stored, so existing records still match. `stage_types` is seeded there too (it was only seeded by `scripts/seed.py`).
- `settings_catalog.py`: one adapter layer so six categories share one API. Lead sources (`lead_sources`) and stages (`stage_types`) keep their tables; contacts still point at them.
- `routes/settings.py`: `/settings/enums` (list, add, rename or hide, remove, reorder), `/settings/company` plus logo upload to `UPLOAD_DIR` (served at `/uploads`), `/settings/roles` (read-only matrix over the real `roles` table).
- Forms accept only active options: stage `loss_reason`, activity `type`, partner `profession_type` (schema enums became strings, routes validate). Stage moves reject hidden stages.
- `GET /contacts/stage-types`, `/contacts/profession-types` and `/lead-sources` read Settings.
- `lead_stages.loss_reason` changes from ENUM to VARCHAR(40): run `scripts/migrate_settings.sql` once on existing databases.
- New env var `UPLOAD_DIR` (default `./uploads`, git-ignored).

## Differences from the original spec
- Roles: the repo has a dynamic `roles` table (7 built-in roles plus custom ones), so the matrix lists those, not three fixed roles. There is no `PATCH /users/{id}/role`; the Team tab uses the existing `PUT /employees/{id}`.
- Lead sources and stages stay in their own tables instead of moving into `enum_values`.
- Seeds use the values already stored (`phone_call`, `price`, ...) rather than the spec's lists, so no data needs migrating.
- `PATCH` and `DELETE` are `/settings/enums/{category}/{id}` because ids overlap between tables. `DELETE` returns 400 for a value in use (the web then offers to hide it).

## Out of scope
- Adding or deleting pipeline stages (rename, reorder and hide only: stage rules and follow-up clocks are in code).
- Editing permissions (the matrix is read-only by design).
- The Flutter app still uses its own fixed lists.

## Verification
`pytest` (tests/test_settings.py: access control, usage counts, locked options, reorder, reactivation, form validation, logo upload, matrix).
